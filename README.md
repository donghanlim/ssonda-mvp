# 쏜다(SSONDA) 로컬 파일럿 MVP

계좌이체를 받는 오프라인 매장이 **기대 결제와 실제 입금을 대조**하도록 돕는 로컬 우선 MVP입니다. `a comma`의 첫 제품인 쏜다의 파일럿 흐름을 재구현했습니다.

## 구현 범위

1. **고객 안내**: 매장 계좌를 복사하고, 이름 뒤에 붙일 3자리 ShotCode를 안내합니다. 고객 링크를 QR로 표시할 수 있습니다.
2. **ShotCode**: `((시 × 60 + 분) + jitter) % 1000`, jitter `0..9`으로 생성합니다.
3. **입금 대조**: 붙여넣은 은행 내역(CSV/탭 표)을 파싱한 뒤 이름+코드, 금액, 60분 시차, 잔액 연속성을 근거로 후보를 제시합니다.
4. **사람 최종 확정**: 후보는 자동 확정되지 않습니다. 운영자의 확정/보류와 메모가 감사 기록에 남습니다.
5. **정산서**: CSV로 다운로드합니다.

## 의도적으로 제외한 범위

- 실제 송금 실행, 결제대금 보관, 환불, 자동 정산 확정
- 로그인, 다매장 권한 분리, Supabase Storage, 서버 OCR
- 민감한 통장 스크린샷 저장

이미지 OCR은 실데이터 업로드 보안, 보존·삭제 정책, 매장 권한 분리가 준비된 다음 단계에서 비공개 스토리지와 비동기 작업으로 연결해야 합니다. 이 MVP에서는 이미지 업로드를 받지 않고 표 복사/붙여넣기만 지원합니다.

## 파일 구조

- `src/core.mjs`: ShotCode 정본 규칙의 JS 이식, 텍스트 파서, 후보 평가
- `engine/shotcode.py`: Python ShotCode 참조 구현
- `app.js`: 고객 안내와 운영자 세션 UI
- `server.py`: 로컬 정적 서버와 로컬 QR SVG 엔드포인트
- `tests/`: ShotCode, 파서, 후보 대조 회귀 테스트

## 파일럿 안전 원칙

- 데이터는 현재 브라우저의 LocalStorage에만 저장됩니다. 종료 전 CSV를 내려받고, 파일럿 후 `모든 세션 데이터 삭제`를 실행하세요.
- 실제 계좌·입금자명·통장 이미지를 이 개발용 MVP에 장기 보관하지 마세요.
- 매칭 후보가 맞더라도 운영자가 장부와 대조해 확정해야 합니다.

## 휴대폰 QR 및 은행 앱 흐름

`127.0.0.1`은 맥 자신만 가리키므로 **휴대폰 QR에는 사용할 수 없습니다.**

1. 맥과 휴대폰을 같은 Wi-Fi에 연결합니다.
2. `python3 server.py`를 실행해 표시되는 `Same Wi-Fi phone test` 주소를 매장 설정의 **외부 접속 URL**에 입력합니다.
3. 기대 결제를 만든 뒤 고객 안내 링크를 새 탭에서 열고 QR을 스캔합니다.
4. 휴대폰의 고객 화면에서 **토스로 계좌·금액 자동입력**을 누릅니다.

토스의 `supertoss://send` URL은 은행명, 계좌번호, 금액을 전달합니다. 다른 은행 앱은 웹에서 이체 입력 필드 전달을 공개적으로 지원하지 않는 경우가 많으므로, 현재는 계좌번호를 복사한 뒤 해당 앱을 여는 보조 흐름을 제공합니다. 이 한계는 웹 앱의 문제가 아니라 각 금융앱의 보안 정책입니다.

실제 매장 사용에는 HTTPS 공개 주소가 필요합니다. GitHub Pages, Vercel 등의 별도 쏜다 주소로 배포한 뒤 그 HTTPS 주소를 외부 접속 URL에 넣으세요.
